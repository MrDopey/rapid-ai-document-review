# Contracts Requirements Quality Checklist: AI Document Review Application

**Purpose**: Formal review-gate validation of the three API contract artifacts — `http-api.md`, `websocket-events.md`, and `agent-tools.md` — for completeness, clarity, consistency, measurability, and contract-test adequacy. Does not assess the spec or implementation.
**Created**: 2026-08-27
**Feature**: [spec.md](../spec.md)
**Contracts**: [http-api.md](../contracts/http-api.md) · [websocket-events.md](../contracts/websocket-events.md) · [agent-tools.md](../contracts/agent-tools.md)
**Depth**: Deep / release gate
**Audience & timing**: Specification author or reviewer, prior to implementation of the API layer

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

**Scope note**: These items interrogate what the *contract documents* say — their completeness, clarity, internal consistency, cross-contract consistency, and adequacy as test drivers. Where a gap is recorded, it means the contract does not specify the behavior, not that the behavior is unimplemented. Items marked `[Gap]` identify decisions the contract needs to capture explicitly before the contract can drive implementation or testing reliably.

## Notes

- Mark items `[x]` only after review confirms the requirement-quality criterion is satisfied
- Leave items unchecked when they still require clarification, correction, or reviewer evaluation
- `/speckit-implement` reads checklist checkbox state as a gate and must not modify markers
- `checklists/requirements.md` has a separate built-in lifecycle maintained by `/speckit-specify` and `/speckit-clarify`
- Items marked `[Gap]` where a decision is missing from the contract indicate behavior the implementation team will have to invent independently — resolving them means writing the decision into the contract document, not re-deciding in code
- Highest-risk clusters by concentration of gaps: the `conflictDetail` shape cross-contract consistency (CHK012, CHK033), the deferred Primary switch terminal conditions (CHK010), the WebSocket ordering edge cases around the Primary auto-apply path (CHK023), and the live-Pi contract test gate (CHK039)
- Contract items do not duplicate `checklists/release-gate.md` items CHK001–CHK090, which interrogate `spec.md` quality; these items interrogate the contract documents themselves
